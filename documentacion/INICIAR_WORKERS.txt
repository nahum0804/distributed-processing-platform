INICIAR LOS WORKERS (worker.py)
==============================

Servidor Central (Nahum):  100.122.10.52:8000
Worker de Kenny (Linux):   100.118.70.69

Orden recomendado:
  1. El servidor ya esta iniciado (REINICIAR_SERVIDOR.txt, pasos 1 a 5).
  2. Iniciar TODOS los workers con este archivo.
  3. Recien entonces sembrar la cola (REINICIAR_SERVIDOR.txt, paso 6).
  Si se siembra antes, el worker local del servidor puede consumir todo
  antes de que los remotos se conecten.

IMPORTANTE
- Copiar los comandos de este archivo, no del PDF (el PDF parte las lineas).
- Cada comando de worker va en UNA sola linea.
- Cada worker necesita un --worker-id distinto.
- Las lineas que empiezan con # son comentarios.


-----------------------------------------------------
A) WORKER REMOTO EN LINUX (laptop de Kenny)
-----------------------------------------------------

# PASO 1. Verificar Tailscale y la conexion con el servidor
tailscale status
tailscale ping 100.122.10.52
# Debe responder "pong"

# PASO 2. Verificar que el servidor responde
curl http://100.122.10.52:8000/tasks/status

# PASO 3. Ir a la carpeta del proyecto
cd ~/Documents/Tecnologico/2026/IIS/Sistemas-Operativos/Proyecto/distributed-processing-platform

python3 worker.py --server http://100.122.10.52:8000 --worker-id laptop-kenny-01 --dataset-dir dataset/real_sample

-----------------------------------------------------
PRUEBAS OPCIONALES DE TOLERANCIA A FALLOS
-----------------------------------------------------

# 1) Worker caido: detener un worker con Ctrl + C mientras procesa.
#    A los 5 minutos (300 s) la tarea vuelve a "pending" y otro worker la toma:
curl http://100.122.10.52:8000/tasks/status

# 2) Fallos simulados: iniciar un worker con --simulate-failures.
#    Falla ~15 % de las tareas; tras 3 fallos una tarea queda en "failed".
python3 worker.py --server http://100.122.10.52:8000 --worker-id laptop-kenny-fallos --dataset-dir dataset/real_sample --simulate-failures


-----------------------------------------------------
SI ALGO FALLA
-----------------------------------------------------
- "No se pudo conectar con el servidor central": Tailscale apagado en
  alguna maquina, o el servidor no esta corriendo.
- "Sin tareas pendientes" todo el tiempo: la cola esta vacia o ya se
  consumio. Revisar /tasks/status y sembrar de nuevo (REINICIAR_SERVIDOR.txt).
- "error: argument --dataset-dir: expected one argument": el comando se
  partio en dos lineas al copiarlo. Pegarlo en una sola linea.
